# Licences: audit, gate and notices (2 November 2026)

Follow-up "Licences: audit, gate and notices" in `docs/BUILD-PROGRESS.md` (the owner, 2 November 2026; `SECURITY.md`,
point 10). PR #458.

## What was built

- **The lists, once:** `.github/licences.yml`, point 10 as SPDX ids, in its two lists by what reaches players
  (`SECURITY.md` as changed by #470): `shipped-licenses`, the strict permissive list for what ships or is built into it;
  `allow-licenses`, the wider list for tools that only run (the permissive ones plus the OSI-approved copyleft and
  weak-copyleft licences: GPL, LGPL, AGPL, MPL, EPL, CDDL, Artistic, UPL, PSF). Never in either: non-commercial,
  no-derivatives or source-available terms, or no licence. The data licences (CC-BY-3.0, CC-BY-4.0, PDDL-1.0) are added
  only for packages named there as data or assets (today `caniuse-lite`), the font licence (OFL-1.1) only for packages
  named as fonts (none yet), never across. Every scope is checked, not only runtime packages (the action's default).
  SPDX expressions are parsed with their brackets (`AND` before `OR`); an exception (`WITH`) is refused. Tested in
  `src/web/test/licences.test.ts`.
- **The gate:** `.github/workflows/licences.yml`, on every pull request into `develop` or `main` (Dependabot's included),
  read-only. Two steps. `actions/dependency-review-action` v5.0.0, pinned to its commit, fails a PR that adds or updates
  a package off the wider list, so nothing off both lists gets in. Then `node scripts/licences.mjs` checks the whole
  lockfile, telling what ships from tools that only run: **shipped** is everything the workspaces' `dependencies`
  (and optional and peer dependencies) pull in, worked out from the workspaces' own `package.json` files and the
  lockfile's tree the way Node resolves names, not from the lockfile's `dev` flags, which a PR could edit; it is held
  to the strict list. Everything else (devDependencies and what they pull in) is a tool and is held to the wider list.
  It also fails a package with no licence, which the action only prints, and a committed `.npmrc` that could change
  where npm fetches from. Today: 11 shipped or may be, 251 tools. The script needs no install.
- **The notices:** the web build (`src/web/vite.config.ts`, `thirdPartyNotices`) collects every package the bundle and
  the engine's worker take in, Vite's own preload helper included, and writes `third-party-notices.txt` beside the game
  with each one's licence text, after a section crediting the samples and the map data. The build fails on a bundled
  package off the strict list, whatever `package.json` calls it (Vite is a devDependency, but its preload helper is
  bundled, so it is held to the strict list there). This is the exact check of what ships; the lockfile check is the
  conservative one before the build. The About page's Credits and the README's link to it. Nine packages ship today: the Anthropic
  SDK and what it pulls in (`@stablelib/base64`, `fast-sha256`, `standardwebhooks`), React, React DOM, `scheduler`,
  Zod and Vite's helper. The file is left out of the service worker's install list (read, if ever, online).
- No licence file added to the owner's code; the notices file says the game itself is all rights reserved.

## Readings taken

- **The action alone does not meet point 10:** `dependency-review-action` fails on a forbidden licence but only prints a
  package with none ("never anything without a licence"), so the lockfile check runs beside it in the same workflow.
  Principle: follow the rule's purpose (item 134).
- **CC-BY and OFL by name, not by guess:** whether a package is data, an asset or a font cannot be read from its
  metadata, so such a package is named in `.github/licences.yml` by a reviewed change, and only then may it use those
  licences (Codex's review). "Public Domain", which has no SPDX id, is accepted by the lockfile check for any package;
  the action cannot be told so and fails one until it is named there.
- **Vulnerability checks off in the action** (`vulnerability-check: false`): the lane is licences; turning the action's
  advisory check on would gate PRs on a new rule nobody asked for. It is this review's one idea instead.
- **A package is named by where npm fetches it,** not by any name in the lockfile: only an entry resolved from
  `registry.npmjs.org` under a package's own name takes that package's data or font licences, so a local tarball, a link,
  a git source or a renamed entry is held to the general list (Codex's security reviews, rounds 3 to 5).
- **Two lists, told apart by `package.json`, then by the bundle** (#470): what the workspaces' runtime dependencies pull
  in is treated as shipped even if the bundle leaves some of it out (`@babel/runtime`, `json-schema-to-ts` and
  `ts-algebra` are types or unused), since a later import could bundle it without touching the lockfile; the build's
  notices step then checks exactly what is bundled, whatever its dependency type.
- **Only Vite's own notice ships for Vite,** not the licences of the packages Vite's command-line tool bundles (its
  `LICENSE.md` lists them), since only the small preload helper reaches the game.
