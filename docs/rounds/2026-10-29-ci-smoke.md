# Side lane: the smoke test in CI (29 October 2026)

PR #199, branch `ci/smoke-on-web`. The Playwright smoke test of the built app (`src/web/smoke.mjs`) ran only by hand,
so the map's overlapping names (item 11f+, #196) went unseen.

## What was built

- `.github/workflows/pages.yml`: the `changes` job gains a `web` output, true when a PR changes `src/web/`,
  `src/engine/`, `src/game/` or `src/llm/` (what the app bundles; the map and its names live in the engine), the root
  `package.json`, `package-lock.json`, `tsconfig.json` or `tsconfig.base.json`; never their `test/` folders or `.md`
  files. A `smoke` job runs on it beside `checks` and the test shards: `npm ci`, Playwright 1.63.0 installed with
  `--no-save` (it is not a project dependency), Chromium cached by version, then the build and the smoke test. Publishing
  `main` also waits on it (success or skipped).
- `scripts/cloud-setup.sh`: Playwright 1.63.0 too, the version cloud sessions have; it said 1.49.1. Each file points to
  the other.

## What it caught

Its first run failed: "babylon over badge of susa", "byblos over traveller k-envoy", the cases #196 fixed. About one run
in two or three failed, on CI's runner and locally under load, with Playwright 1.49.1 (Chromium 131) and 1.63.0 alike.
A first fix, placing again when each running transition really finishes, did not cure it, since nothing was moving.

The cause (found by the escalation helper, then checked here): Chromium fits an SVG text's glyphs to its scale on screen,
the `.mapzoom` transform included, at whatever moment it last laid that text out, mid-glide or not, and lays it out
again when it likes. So a name's box grows or shrinks by a few pixels with nothing changed: in one captured failure, at
zoom 1.60 with nothing running, Babylon's name measured 308.1 to 351.2 px when placed and 308.1 to 354.2 px at the
check, into Susa's walls at 353.1; transform, sizes and classes identical. Laying out the shown names again on a still
map changed 9 of their 10 boxes.

The fix is one line, `text-rendering: geometricPrecision` on the map's text (`src/web/src/styles/app.css`): the text is
laid out at its own size and scaled with the map, so its box no longer depends on the zoom it was last laid out at
(widths identical at every zoom in a standalone test; no box changed on relayout in the app). The cost: map text is no
longer hinted to whole pixels, which hardly shows on a phone. The smoke test passed 6 of 6 runs under load with it.

## Proof and times

- Skipped where the app is untouched: run 40949702233 (workflow and script only), `smoke` skipped.
- Runs where it is touched: run 40955857200, `smoke` passed in 2 min 44 s, beside a longest test shard of 4 min 54 s,
  so a code PR's checks take no longer. Locally: build and smoke about 2 min 20 s.

## Readings taken

- **The engine counts as able to break the drawing.** The map's data, names and coordinates live in
  `src/engine/src/model/`, and the smoke test plays script kings through the engine. Alternative: `src/web/` only,
  cheaper, but blind to a map-data change. Principle: the guard covers what it guards.
- **The fix rides this PR.** The job cannot merge red, the bug is the app's (a player sees a name over a badge), and no
  open PR touches the map's stylesheet. Alternative: a lane of its own first.
- **The workflow file is outside the filter,** so this PR could show the skip; a later change to the job shows itself by
  touching a file under `src/web/`.
