# The sync script

A change to the core reached each project only through a sync PR the design session opened by hand. The owner asked for
it to happen by itself when the core updates (core archive 124). Now:

- **`scripts/sync.mjs`**, run from a project's root: writes `core/` whole at the core's newest `main` (or a given
  commit), moves the manifest's "Core:" line, and moves each call to a core workflow whose workflow changed, listing
  them, since that needs the owner's yes. It commits and pushes nothing. Git and Node's own modules only.
- **The orchestrator's wake** (`modules/orchestrating.md`): when the core's `main` is past the pin, a routine lane runs
  it and opens the sync PR.
- **Here** (`AGENTS.md`): a change is done when a sync PR carries it in every project; the design session checks it.

Tested on a project copy pinned to the core of the morning (`850b4dc`): `core/` came out equal to the core at the new
pin, file for file; the manifest moved; the call to `personal-terms.yml` (changed since) moved and was listed, the call
to `copies.yml` (unchanged) stayed; run again, it said there was nothing to sync.

## Readings taken

1. **Not a GitHub workflow:** a PR a workflow opens with its own token runs no checks, so it could never merge past the
   required ones; another token would be a secret in a workflow. A script a session runs needs neither.
2. **Only the calls whose workflow changed move,** exactly the ones `core.yml` would fail, so a sync PR touches
   `.github/` only when it must.

Questions for the owner: none.
