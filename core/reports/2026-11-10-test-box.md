# The test box

A security review of Amarna Letters' step 3 (its #871, on the copied `core/setup/server.md`) found that on a machine
where agents run side by side, the tests run a project's packages under the account that holds the GitHub token, so a
bad package that slipped past review could take it. The token can open and merge PRs, and Codex's reviews are not a
check GitHub enforces, so a stolen token could merge past them.

- **Floor rule 18 (needs the owner's yes, relayed in the PR):** project code (a build, the tests and the packages they
  run) runs where no sign-in can be read, in a throwaway box given a copy of the clone, with network only where the run
  needs it; only an agent, after checking its change, pushes. The agents keep full internet (core archive 127).
- **`setup/server.md`:** the box (rootless Podman or Docker, and a wrapper script the agents run instead of a project's
  install, build or test command), written and tested when the machine is set up; the agents' instructions send those
  commands through it.

What changes in every project: nothing until such a machine runs; then a test run can no longer reach a sign-in.

Readings taken: none. Questions for the owner: none.
