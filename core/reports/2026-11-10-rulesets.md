# The rulesets: code scanning required, Copilot advisory

The owner set a game's ruleset to require code scanning results and asked for the same in every project (core archive
130).

- **`README.md`, "Setting up (the owner's part)":** each project's ruleset, as the projects now have it:
  - deletions restricted and force pushes blocked;
  - a pull request required, with no approvals;
  - status checks required, with branches up to date;
  - code scanning results required from CodeQL, blocking on security alerts High or higher and alerts Errors;
  - code quality results required at Errors;
  - Copilot's code review may be requested automatically.

  No project runs GitHub's Code Quality analysis yet. The owner reads the code quality rule as acting only where it
  runs; GitHub's guide warns that it can block every merge without it. The first merge under the rule settles which.
- **Floor rule 9 (`floor/topics.md`; needs the owner's yes, relayed in the PR):** a CodeQL false alarm still merges
  once explained and confirmed. Where the ruleset blocks on the alert, though, the PR waits for the owner to dismiss it,
  asked for in an issue assigned to him, since no agent can see or dismiss alerts.
- **`modules/reviews.md`:** Copilot's code review is advisory. The builder fixes what is real and answers the rest in a
  line; no merge waits for it, and it counts toward no 10.

What changes in every project: GitHub itself now refuses a merge with a high or critical CodeQL finding open. Such a
false alarm waits for the owner. Copilot's comments, where he turns its review on, are fixed or answered, never waited
for.

Readings taken: none. Questions for the owner: none.
