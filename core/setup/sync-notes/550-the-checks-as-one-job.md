- **17 November 2026, the checks as one job.** Done when, in a private repository, the project's call to the core's `core.yml` also runs its other checks that need no secret, as steps of its one job (#376), as the starter kit writes it for a private project (`core/scripts/init.mjs`, `oneJob`): it passes `copies:` and `sizes:` (the copies check's config and marks), `description: true` and, for each of npm and NuGet the project's packages come from, `signatures:` (the folder of `package-lock.json`) and `nuget:` (the licence check's config, with `advisory: true` where its call to `nuget.yml` passed it), its `pull_request:` trigger takes the description check's types (`[opened, edited, reopened, synchronize, ready_for_review]`, the job skipped on a draft as the entry of 16 November has it), and the project's own calls to the core's `copies.yml`, `pr-description.yml`, `signatures.yml` and `nuget.yml` are taken out. A pull request then starts two jobs, this one and `personal-terms`, where it started four or five: at the median, about 22 billed minutes a pull request become 12 for a project that took the entry of 16 November, and about 31 become 19 for one that did not (#377). The job's time is the sum of its steps', and on a pull request that changes a package file each edit of its description runs the package check again. Its status is one, `core / core`, in place of three or four: where a ruleset requires `copies`, `pr-description`, `signatures` or `nuget` by name, the owner takes those names out of it before the pull request that takes the calls out merges, or it waits for checks that no longer run; `core / core`, which it may already require, still reports, though it does not say which checks the call names: a pull request that takes an input out of the call still passes it, and only the reviews of that protected file hold its inputs, as they held its calls before. `core/scripts/fresh.mjs`, which every sync runs, lists the call a private project's calls differ from (and no longer the `paths:` of the entry of 16 November, since the kit writes a private project no `nuget.yml`); `core/scripts/steps.mjs` reports a call to `core.yml` that runs part of the one job and leaves out a check the project ran, or runs one the project still calls on its own. A session may run the same steps by hand, a tool and no duty: `node core/scripts/checks.mjs`. A public repository's minutes are free: it keeps its calls, as the kit still writes them for a public project, and is asked nothing. A project that changes nothing runs every check as before, each still its own job; the core's `copies.yml`, `pr-description.yml`, `signatures.yml` and `nuget.yml` now run their steps through the copy's `scripts/checks.mjs`, and each says the same as before. The cost: a workflow's change, one small pull request with floor rule 3's two security reviews; and, where a ruleset names those checks, a setting of the owner's.
