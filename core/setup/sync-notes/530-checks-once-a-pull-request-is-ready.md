- **16 November 2026, checks once a pull request is ready.** Done when, in a private repository, each of the project's calls to the core's `core.yml`, `copies.yml`, `personal-terms.yml`, `signatures.yml` and `nuget.yml` also starts when a pull request is marked ready and skips its job on a draft, as the starter kit writes them (`core/scripts/init.mjs`, `READY_ONLY`): `ready_for_review` among the `types:` under its `pull_request:` (where it lists none, `types: [opened, reopened, synchronize, ready_for_review]`), and `if: ${{ !github.event.pull_request.draft }}` on the job that calls the core's (#375). A push to a draft then bills none of those jobs and marking it ready runs each once: about 22 billed minutes for a pull request at the median where it was about 31, and no more however often a draft is pushed to. A draft shows no check until it is marked ready; on a draft, a ruleset that requires one of them waits or counts the skip as passed, and either way a draft cannot merge, while marking it ready runs the check. `core/scripts/fresh.mjs`, which every sync runs, lists the lines a private project's calls lack; `core/scripts/steps.mjs` reports a call whose job skips a draft while its trigger leaves `ready_for_review` out, which would leave that check never run on the pull request once it is ready. A public repository's minutes are free: it may keep its checks on each push, and is asked nothing. A project that changes nothing runs every check as before.
