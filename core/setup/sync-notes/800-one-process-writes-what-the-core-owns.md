- **22 November 2026, one process writes what the core owns.** Nothing to do by hand (#1083). From this sync on, the sync, once it writes the copy, runs the one process the starter kit runs too (`core/scripts/converge.mjs`), which writes what the core owns, takes out a call of the core's whose check the one job of the `core.yml` it ends with runs, and leaves the rest as the project's, as the core's `AGENTS.md` sets out ("One process takes the core in"), naming each file it leaves as a difference. A sync pull request that carries what it wrote stays a pure sync (`core/scripts/pure-sync.mjs`, run from the core's `main`; floor rule 8), so the workflow changes a release brings need no review in the project. The sync that brings this runs the earlier copy's sync script, which does not run the process: the session that syncs runs `node core/scripts/sync.mjs <the manifest's pin>` once more in the sync's branch, which at the same pin moves nothing, runs the process with the earlier kits and prints every report a sync prints, for the sync pull request's description, and commits what it writes and takes out in the sync's pull request. A pull request that afterwards changes a file or part the core marks so that it is not as the core writes it fails the copies part's check, saying the mend. Done when `AGENTS.md` and `CLAUDE.md`, where they stand, hold the core's part between its marks, which the process writes at its first run.
