- **16 November 2026, what a screen is held to.** Done when, in a project people use through a screen, its *direction* stands (`docs/direction.md`, unless its manifest names another file in that row), as `core/tasks/screens.md` says (point 1): the builder of the project's next pull request that changes a screen writes it first, from what the product already shows, and puts two or three sample screens before the owner there, which nothing waits on. A project with no screen does nothing. Nothing fails and no check is turned on: each screen check is off until the project names it in its *screen checks* (`core/scripts/screens.mjs`), and from this sync on a pull request that changes a screen gets the critique (`core/tasks/reviews.md`). Where the manifest's "Modules:" is a list, it takes `screens.md` or leaves it out with its reason.
