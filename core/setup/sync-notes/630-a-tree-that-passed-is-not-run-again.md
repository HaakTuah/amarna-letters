- **18 November 2026, a tree that passed is not run again.** Done when each job of the project's that runs the selection (`core/scripts/select.mjs`) on a push, in a workflow that a pull request runs too, gives it `--passed` with the name of the check that gates its tests, on a push's first run alone, with the run's token on that step on a push alone and `checks: read` beside `contents: read` in the job's permissions (`core/tasks/tests.md`, "A tree that passed is not run again"; #457): in bash, `node core/scripts/select.mjs --env RUN ${SELECT_PASSED:+--passed "$SELECT_PASSED"}`, with `SELECT_PASSED: ${{ github.event_name == 'push' && github.run_attempt == 1 && 'tests' || '' }}` (the job's own check, as a ruleset requires it) and `GH_TOKEN: ${{ github.event_name == 'push' && github.token || '' }}`; and the step that runs the tests runs none where `RUN` says `none`, which the selection writes where it selects nothing, since a runner given no file runs every test (`if [ "$RUN" = all ]; then <the whole suite>; elif [ "$RUN" != none ]; then <the runner> $RUN; fi`, or an `if:` on each step whose parts joined by `&&` hold `RUN` in one part alone, nothing but `env.RUN == 'all'` and `contains(env.RUN, ' <file> ')` joined by `||`, both false for `none`, as the core's own `tests.yml` writes them; any other shape, as `env.RUN != 'all'` or a negation, cannot be read to keep `none` out, and the step reports it). Then a push that merges a pull request's head whose tree it holds (the head was up to date), whose change selects the whole suite as that pull request's run selected it, and whose check passed on that head as GitHub Actions posted it, selects no test: the run on the default branch for a tree that passed whole is skipped, and asks GitHub one question with that token. Where any of that cannot be told (a squash or a rebase, a tree that differs, a selection, no answer), the whole suite runs as before, and so it does on a re-run and on a schedule. `--passed` stays off a job, or an entry of a job's matrix, that a pull request does not run, whose suite ran nowhere else; a job that runs on a push alone is not read by the step; and a job whose tests read what no tree holds (a release's tag, the day) is left without it. That the head held the default branch rests on floor rule 12, which merges a pull request brought up to date with it. A project whose job selects nothing on a push, or that has no such job, as the starter kit writes none, has nothing to do. Nothing fails meanwhile. The cost: a workflow's change, one small pull request with floor rule 3's two security reviews; it saves a whole run of the suite on each merge of an up-to-date pull request that ran it whole.
