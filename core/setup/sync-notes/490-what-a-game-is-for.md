- **16 November 2026, what a game is for.** Done when, in a game, its *game page* stands (`docs/game.md`, unless its manifest names another file in that row), as `core/tasks/game-design.md` says ("Every game says what it is for, on one page"): the builder of the game's next pull request that adds a feature writes it first, quoting the owner's past words, with the stand-in's reading, marked so, where they name no experience, which nothing waits on. A project with no game does nothing. Nothing fails and no check is turned on: the check `first-choice` is off until the project names it in its *screen checks* (`core/scripts/screens.mjs`), and from this sync on the builder of a change to a game's rules reports its five standing measures against targets that are first guesses ("Standing measures from the simulations, for every game"). Where the manifest's "Modules:" is a list, nothing changes: the rules are in `game-design.md`. The cost: a read, and the page in the next pull request that adds a feature.
