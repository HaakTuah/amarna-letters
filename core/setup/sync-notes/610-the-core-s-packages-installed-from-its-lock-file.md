- **18 November 2026, the core's packages installed from its lock file.** Done when each job of the project's own workflows that runs a `.mjs` script under `core/scripts/` runs `node core/scripts/install.mjs` before it (#654). The core's scripts now load the packages of other publishers they run (a YAML parser, and a Markdown lexer for the pointer check) from `core/.packages/node_modules/`, which `core/scripts/install.mjs` installs from `core/.packages/package-lock.json` with npm, running no install script; the copy's own `.gitignore` keeps that folder out of git, and its package list stands in the dot folder `core/.packages/`, which no workspace pattern of the project's own package list takes in. The sync installs it, the core's workflows a project calls install it in each job, and a session's start installs it; where it is missing, a check says it did not run, with that command as its mend. A project whose workflows only call the core's has nothing to do. In one that runs `pointers.mjs` itself (or through `checks.mjs copies`), the pointer check says as a warning that it did not run, failing nothing, until its job installs first; one that runs `copies.mjs` so has its config's shape left unchecked, said as a warning, the rest of the check run. In one that runs `workflows.mjs` itself (or through `checks.mjs copies`), the check says as a warning that it did not run the checks that read YAML (a file that is no YAML, a call a draft skips), failing nothing, until its job installs first, its sync pull request too; its other checks run. `comment-only.mjs` and the YAML readers of `yaml-keys.mjs` are run by the core's own workflows, not by a project's. The step `if [ -f core/scripts/install.mjs ]; then node core/scripts/install.mjs; fi` goes in a pull request of its own, before the sync or after it (guarded, so it passes on a copy older than the install script). The cost: a step in each such job, and a few seconds of install in each job that runs a check. From #1093 nothing of this is asked: each script of the copy installs the core's packages itself before it reads, or says it did not run and why, failing nothing; an install step a project added stays harmless.
