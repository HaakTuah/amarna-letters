- **19 November 2026, why a file past its split mark stays whole.** Nothing to do for what stands (#469). From this sync on, the reading-size check (`core/scripts/reading-size.mjs`, in the copies check) reads each line of `"past"` in the project's *size marks* as a mark alone or as `{ "mark": <bytes>, "why": "<why no split lets anyone read less, or the split's issue>" }`, and a file past the split mark that a pull request changes fails where its line is one that pull request writes with no why (a reason, or the split's issue), or where the file has grown a quarter past its line's mark, the failure saying how to ask the question (`core/tasks/cleaning.md`, "Size asks"). A line written as a mark alone that stood before stands as it did, failing only where its file grows past its mark, as before, with a note asking for its why. Nothing that stood fails, and no job is added. The cost: a line of the marks, a rule file's change, written when a line is next written.
