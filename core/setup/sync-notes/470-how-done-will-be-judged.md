- **16 November 2026, how done will be judged.** Done when, where the manifest's "Modules:" is a list, it takes `done-when.md` or leaves it out with its reason. A feature's issue (the kind `feature`, by its label or under "What to read") now holds "Done when", two to six lines in three shapes, each naming its proof, and the pull request that closes it says under "Proved by use" what it ran and saw for each (`core/tasks/done-when.md`). From this sync on the description check asks, of each pull request opened after it, that a feature's issue it adds to the *progress file* holds the lines in their form, and that one closing a feature's issue gives that evidence, its failure saying the mend; an issue its token cannot read is asked nothing, and it says so. A pull request that queues or closes more than a dozen items fails, saying to split it, since each costs calls on the run's token; one whose read the rate limit refused fails, saying to run the check again. Nothing that stood before is read: an issue already queued is not asked again. `core/scripts/fresh.mjs` lists the idea form's new heading "Done when" and its word on the kind as a difference, a small task. The cost: a word of the manifest and the idea form's lines, one small pull request of a builder's.
