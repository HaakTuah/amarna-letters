- **23 November 2026, a commit's address a no-reply one.** Done when every machine that commits in the project, the owner's own computer included, has git's `user.email` set (in the repository, or for the machine) to a no-reply address: the account's (Settings, Emails, ending `@users.noreply.github.com`), or the agent tool's own (`noreply@anthropic.com`, which Claude Code writes) (#460, point 2). From this sync on, the personal-terms check fails a pull request whose own commits carry another address in their author or committer line, whether or not `PERSONAL_TERMS` is set, naming each commit and line, never the address, and says how the session mends it there: that address set, and the pull request's commits rewritten with it (`git rebase --exec 'git commit --amend --no-edit --reset-author' origin/main`, then `git push --force-with-lease`), never `main`. A commit GitHub itself makes and signs (a merge, an edit on github.com) passes under the profile it writes, whatever its address. Commits `main` already holds are left as they are: history is not rewritten. A project whose commits are all made under such an address has nothing to do. The cost: none while its commits pass; else the mend, in the pull request that fails.
