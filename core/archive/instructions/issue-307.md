# The reasons behind the core: issue #307

The index, and how an item is written: `archive/instructions.md`.

#307. **15 November 2026**, #307. The reviewers are tested: each in the order is given a pull request with a fault of
     each blocking kind planted in it, with the staged cases each month and again once a reviewer's model or the
     review guidelines change, and one that misses a kind gets a worked example for it or moves down the order; the
     review guidelines carry a worked example for each kind of blocking point, one that blocks and one that does not;
     and a change that edits a test it also makes pass says so, a check listing every assertion it takes out or changes
     and every case it skips for the reviewer to rule on: every pull request rests on its reviews, a model that judges
     work leans kind until calibrated with examples, and a builder pressed to pass can loosen the test instead of
     mending the code. The owner agreed to it among the additions a session set out after checking the core's rules
     against the field's practice, the owner having asked what mistakes the process does not prompt the models to
     avoid or detect, and set the test's timing by time rather than by release, since releases can come daily. It
     stands behind "The reviewers are tested" in `tasks/reviews.md`, the worked examples in the review guidelines, "A
     test taken out or weakened is said" in `tasks/code-shape.md`, `scripts/weakened.mjs` and the staged case `review`.
