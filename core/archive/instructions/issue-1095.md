# The reasons behind the core: issue #1095

The index, and how an item is written: `archive/instructions.md`.

#1095. **22 November 2026**, #1095, a design the owner agreed to in a chat session with the adviser. The adviser had a
     helper read every step of the core and set out which a script could do in place of an agent, five changes ranked
     and the gaps found; the owner agreed to all of it, for release 6 before the cut, asking that the update be as
     robust and smooth as it can be and that nothing be left out. Of its points 2 to 6: the steps are read with the
     core's packages installed, or stop in one line that says why and the mend, never many steps "could not read"; the
     stale-package report runs with the sync; a step whose findings only a tool fetched at set-up reads is read where the
     session fetched it, and stays unread elsewhere; a check's config the project holds gains the kit's keys it lacks,
     every value of the project's kept; and the fresh start compares all the kit writes. A step left unread, or a config
     a sync cannot complete, is one more thing an agent rebuilds by hand in every project, and is where an update goes
     wrong. It stands behind "One process takes the core in" and "A release says what it asks, step by step" in
     `AGENTS.md`.
