# The reasons behind the core: issue #954

The index, and how an item is written: `archive/instructions.md`.

#954. **20 November 2026**, #954. A run of the core's tests started by hand names in its input the parts and the system
     to run and runs those jobs alone, in full where it names none; a builder whose change needs the Windows suites
     names the parts its change reaches, and starts a full run only where its change reaches every part; a run so
     narrowed is never read as a full one, by the release or by the hourly run's skip. Between 09:45 and 11:01 UTC
     that day the account's 40 jobs at once stood full for 63 of 76 minutes, and five runs started by hand in full,
     each change needing one Windows part, took 38% of the runner minutes. The owner agreed to the design the adviser
     set out, ahead of other work as a fix to the flow of work. It stands behind a clause of "The slow suites run once
     per batch, wherever they run" in `tasks/tests.md`.
