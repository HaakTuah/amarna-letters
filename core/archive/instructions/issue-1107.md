# The reasons behind the core: issue #1107

The index, and how an item is written: `archive/instructions.md`.

#1107. **22 November 2026**, #1107, a design set out by the owner's adviser and agreed to by the owner, in a chat
     session, after the adviser compared the core with a published standard for code agents build, which asks for
     tests, mutation testing and measures of the code's shape. The core's own code is held to that standard, and so is
     every project's: the *mutation tool* of a project with tests is named from a list the core keeps, by the
     languages of its code, each tool under the floor's rules for dependencies and licences, and the row says `none`
     with its reason where the list has no tool that fits or there are no tests; the owner may turn the measure off
     with `none` and a reason, and nothing else does, and the same holds of the shape check, its manifest's row. It
     adds no job and fails nothing before the baseline stands. The reason: a project that takes the core on trust set
     no tool, so its tests' strength was never measured, and a check a project could leave off by writing nothing
     would hold nothing. It stands behind "How strong the tests are is measured on the lines a pull request changes"
     and "Only the owner turns the shape check off" in `tasks/code-shape.md`.
