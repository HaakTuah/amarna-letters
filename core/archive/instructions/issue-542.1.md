# The reasons behind the core: issue #542.1

The index, and how an item is written: `archive/instructions.md`.

#542.1. **17 November 2026**, #542, points 1 to 4. A check that fails on the default branch's newest commit has an
     owner: the session whose merge it followed while it runs, else the orchestrator at its next wake, else the next
     builder at its start; its owner runs it again once where its mend says so or a source could not be reached, files
     a pass on the second run as an unsteady test to be mended at its cause, and files a second failure as a bug naming
     the merge it followed; the scheduled look keeps an issue open while one has failed. A suite had failed on the
     core's default branch for a fetch that failed, its mend said to run it again, and no session was left to read it
     while a release waited on a green branch. The owner agreed to the design the issue sets out. It stands behind "A
     check that fails on the default branch has an owner, and is run again once" in `tasks/tests.md`.
